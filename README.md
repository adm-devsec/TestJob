## Тестовое задание

.NET Core 10 (кроссплатформенный linux / windows)

Необходимо реализовать 1 REST API функцию.
Метод - POST, в теле запроса передается JSON.

Сделать:
1) сервис с бизнес-логикой
2) api-контроллер, передающий данные в сервис

Тестовые входящие данные (JSON) приведены в файлах json_payload_1.txt, json_payload_2.txt.

## Описание входящего объекта:

* selector - строка - CSS-селектор для поиска html-элементов на веб-странице
* attribute - строка - наименования HTML атрибута
* url_b64 - строка - строка URL, закодированная в Base64
* encrypted_text_bytes_b64 - массив байтов, закодированный в Base64 - это результат шифрования строки алгоритмом AES256 в режиме ECB с PaddingMode.None
* key_bytes_b64 - массив байтов, закодированный в Base64 - это ключ для AES256, который использовался для шифрования текста 
* page_b64 - строка - код HTML-страницы, закодированный в Base64       // код страницы в открытом виде приведен в файле web-page.txt для информации и проверки результатов работы



## Задача для данной API-функции:

1) Сделать валидацию входящего объекта с помощью FluentValidation.

2) Раскодировать URL и PAGE из base64 в открытый вид.

3) С помощью библиотеки AngleSharp:
	- провести парсинг page (преобразование HTML-текста в DOM-объект)
	- выбрать все элементы по CSS-селектору, указанному во входящем объекте
	- определить количество полученных элементов
	- для каждого элемента получить значение (строка) атрибута HTML, указанного во входящем объекте (например href для ссылок)
	- сформировать List<string> cо значениями этих атрибутов

4) Записать в БД postgres в таблицу links информаций о ссылках: id (bigint, auto increment), url, полный html код ссылки (<a href="....">). Использовать Dapper для работы с БД.


5) с помощью регулярного выражения получить значения всех email-адресов в коде страницы. Посчитать их количество. Сформировать List<string> с полученными email

6) С помощью ключа из входящего параметра параметра key_bytes_b64 расшифровать текст из входящего параметра encrypted_text_bytes_b64. Использовать для расшифровки стандартные библиотеки шифрования .NET. Использовать алгоритм шифрования/дешифрования AES 256 в режиме ECB с PaddingMode.None. 

7) реализовать обработку исключений в связи возможными некорректными входящими значениями: 
	- ошибка при декодинге base64 в URL
	- ошибка при декодинге base64 в Page
	- отсутствие какого-либо параметра во входящем объекте
	- пустой селектор во входящем объекте
	- пустой атрибут во входящем объекте
	- иные ошибки

8) ответ на запрос представляет из себя объект, сериализованный в JSON, с отступами для удобного чтения, со следующими полями:

* is_error - int - есть или нет ошибка при обработке запроса
* error_code - string - текстовый код ошибки (придумать самостоятельно)
* error_message - string - для "иных ошибок" - exception.errormessage
* elements_count - int - количество выбранных по селектору элементов
* emails_count - int - количество найденных email
* url - string - URL в открытом виде (раскодированный из base64)
* decrypted_plain_text - string - текст расшифрованный из полученного шифротекста и ключа
* elements_attr_list - List<string> - список выбранных из обнаруженных элементов атрибутов
* emails_list - List<string> - список email

9) по пути /api/swagger должен открыться swagger для удобного тестирования api-функции


## Задача по проекту

1) Сделать docker compose проект из двух контейнеров (ваше приложение API, БД PostgreSQL 18). БД должна сохранять состояние при перезапуске проекта docker compose.
2) В контейнер с приложением делается монтирование папки с исходным кодом проекта, при запуске контейнера каждый раз происходит билд приложения asp.net и запуск в этом же контейнере.
3) В корне проекта должен находиться файл compose.yml для запуска docker compose проекта
4) Для сериализации / десериализации JSON использовать стандарную библиотеку .NET Core 
5) Везде используется кодировка UTF-8
6) Для дешифрования использовать стандартные функции .NET
7) Использовать скомпилированное регулярное выражение
8) Функция, выполняющая обработку, должна быть асинхронной. Использовать доступные асинхронные функции внутри (парсинг HTML, применение регулярных выражений, сериализация и прочее ). Забыть предыдущие задачи. Объяснить пользу от использования асинхронных функций в RESP API, быть готовым обосновать отказ от использования асинхронных аналогов в некоторых местах. (Подробнее - https://learn.microsoft.com/ru-ru/dotnet/csharp/programming-guide/concepts/async/ , https://learn.microsoft.com/ru-ru/dotnet/csharp/async)
9) Выложить проект в публичный личный репозиторий на GitHub.
10) ВАЖНО! В корень проекта положить 2 файла с JSON - результатом работы API функции для входящих данных json_payload_1.txt, json_payload_2.txt
